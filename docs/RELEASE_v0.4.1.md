# v0.4.1 — combined daily production upload

Normal daily use now requires one **Excel Import → Daily Production Upload → Preview → Confirm**. Select the same values-only `Upload_YYYY-MM-DD_timestamp.xlsx` generated by the October workbook helper. It must contain both `Daily_Actuals` and `Historical_Daily_MIS_Import`; no daily workbook restructuring is required.

The combined preview shows total business-row counts and separate customer MIS and stage actual counts. Customer daily plans/dispatch and stage actuals commit together. Parent dispatch is reconciled across both tabs and is recorded once in MIS. Missing counterparts, mismatched quantities, duplicate rows, invalid pieces or an unknown stage prevent confirmation. One faulty stage rolls back the customer plans as well. Exact-file deduplication is scoped to this import kind, so a workbook previously imported through a separate card can be previewed here. Repeated unchanged records remain unchanged.

Admin and Planning can confirm combined uploads because they include customer plan changes. Production retains the existing stage-only actual importer. Existing records may be corrected only with a reason from the reconciled parent dispatch row or the application change-reason field. For example, populating a previously uploaded zero customer plan requires a genuine correction reason. A revised customer requirement cannot be silently replaced by an older Excel plan. Month-close and user-bound correction grants, audit evidence, stale-preview protection and atomic confirmation remain enforced.

**Flow Definition** and **Stage Schedules** remain setup/revision imports. Historical MIS and stage-only cards remain available for their specific purposes; normal daily users do not need to upload at both cards.

The approved process chart now displays full **stage names vertically**, with sufficient lower margin and spacing. Data labels remain on. Chart drill-down uses the stage ID, so duplicate stage names do not select the wrong stage. Branch/variant filters and the detailed table remain available.

## Windows update in the active installation

For this installation, copy the new application files into `D:\Machine Shop MIS`, preserving `.env` and the entire `database` directory. Use its existing Compose project and database mount. Do not switch to `D:\MISReviewWebApp` or another PostgreSQL volume.

Run `update_in_place_windows.bat` from the existing folder after PostgreSQL is running. The launcher now pauses on failures as well as success, including folders containing spaces. Database readiness is checked before stopping application writers. The updater builds the application, stops writers, creates a PostgreSQL custom-format backup, checks its archive index and SHA-256, then restarts the application on its existing mount. Linux uses the corresponding safe update script. Never use `docker compose down -v`.

After “Update ready,” refresh with Ctrl+F5 and use the new **Daily Production Upload** card. No schema migration beyond the existing Alembic head `0004_process_flows` is required for this release. Existing application data is not automatically rewritten. P2 AFMS/MQTT and Power BI integration remain deferred.
